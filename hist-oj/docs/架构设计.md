# Hist-OJ 架构设计文档

## 概述

Hist-OJ 是 HOJ 的扩展服务，提供基于 Elo 算法的 Rating 计算功能。服务采用 Go 语言开发，使用分层架构设计，与 HOJ 后端共享数据库和 JWT 认证系统。

## 核心模块

### API 层 (`internal/api/`)

**职责**: 处理 HTTP 请求和响应

- **routes.go**: 定义路由和中间件
  - `/api/rating/user/:uid` - 获取用户 Rating（公开）
  - `/api/rating/history/:uid` - 获取 Rating 历史（公开）
  - `/api/rating/color/:rating` - 获取 Rating 颜色（公开）
  - `/api/rating/contest/:contestId` - 获取比赛参赛者 Rating（公开）
  - `/api/rating/calculate/:contestId` - 手动触发计算（管理员）
  - `/health` - 健康检查（公开）

- **handler.go**: 请求处理函数

### 服务层 (`internal/service/`)

**职责**: 业务逻辑实现

- **rating.go**: Rating 计算服务
  - `CalculateContestRating()` - 计算比赛 Rating
  - `CanCalculateRating()` - 检查是否可以计算

- **query.go**: Rating 查询服务
  - `GetUserRating()` - 获取用户 Rating
  - `GetRatingHistory()` - 获取历史记录
  - `GetRatingColor()` - 获取颜色信息

### 客户端层 (`internal/client/`)

**职责**: 外部系统交互

- **hoj_api.go**: HOJ 后端 API 客户端（使用 Resty）
  - `GetContestOutsideScoreboard()` - 获取比赛外榜
  - 支持重试机制和超时控制

- **database.go**: 数据库连接管理（使用 GORM）
  - 连接池配置
  - 自动迁移

### 中间件层 (`internal/middleware/`)

**职责**: 认证和权限控制

- **auth.go**: JWT 认证
  - `JWTAuthMiddleware()` - 必须认证
  - `OptionalAuthMiddleware()` - 可选认证

- **role.go**: 角色权限验证
  - `AdminAuthMiddleware()` - 管理员权限（root/admin）
  - `RootAuthMiddleware()` - 超级管理员权限（root）
  - `RoleAuthMiddleware()` - 自定义角色权限

### 定时任务层 (`internal/schedule/`)

**职责**: 定时任务调度

- **scheduler.go**: 定时检查已结束的比赛并自动计算 Rating
  - 使用 Cron 库实现
  - 可配置检查间隔（默认 5 分钟）

### 工具层 (`internal/utils/`)

**职责**: 通用工具函数

- **calculator.go**: Rating 计算算法（Elo 算法）
- **color.go**: Rating 颜色和等级映射
- **logger.go**: 日志系统（Zap）

### 数据模型层 (`internal/model/`)

**职责**: 数据结构定义

- **rating.go**: Rating 相关模型
  - `RatingHistory` - Rating 历史记录
  - `ContestRatingStatus` - 比赛 Rating 状态
  - `UserRecord` - 用户记录（对应 HOJ 表）

## 核心业务流程

### Rating 计算流程

```
定时任务触发（每 N 分钟）
    │
    ▼
检查已结束的比赛
    ├─ 比赛状态 = 已结束
    ├─ is_rated = 1
    └─ rating_calculated = 0
    │
    ▼
获取比赛排名
    └─ 调用 HOJ API: /api/get-contest-outside-scoreboard
    │
    ▼
获取参赛者当前 Rating
    └─ 查询 user_record 表
    │
    ▼
计算 Rating 变化（Elo 算法）
    ├─ 计算期望排名
    ├─ 计算实际排名得分
    └─ 计算 Rating 变化值
    │
    ▼
保存结果
    ├─ 插入 rating_history 表
    └─ 更新 user_record.hist_rating
    │
    ▼
更新比赛状态
    └─ 标记 rating_calculated = 1
```

### Rating 查询流程

```
API 请求: GET /api/rating/user/{uid}
    │
    ▼
查询用户 Rating
    └─ user_record 表
    │
    ▼
查询最高 Rating
    └─ rating_history 表 MAX(new_rating)
    │
    ▼
获取颜色信息
    └─ 根据 Rating 值匹配等级
    │
    ▼
返回结果
```

## 权限系统

### JWT 认证

- **复用 HOJ 的 JWT 系统**，使用相同的 `jwt-token-secret`
- **算法**: HS512
- **Token 格式**: 直接是 JWT 字符串（无 Bearer 前缀）

### 权限策略

| 接口类型 | 中间件 | 说明 |
|---------|--------|------|
| 查询接口 | 无 | 完全公开，无需认证 |
| 计算接口 | `AdminAuthMiddleware` | 需要管理员权限（root/admin） |

## 数据库设计

### 核心表结构

- **rating_history**: Rating 历史记录表
- **contest_rating_status**: 比赛 Rating 状态表
- **user_record.hist_rating**: HOJ 内部比赛 Rating（与 Codeforces Rating 分离）

### 数据流

```
比赛结束 → 定时任务检测 → 获取排名 → 计算 Rating → 保存历史 → 更新用户 Rating
```

## 部署架构

### Docker 部署

- **端口**: 8080
- **健康检查**: `/health` 接口
- **网络**: 需要加入 HOJ 的 Docker 网络
- **数据库**: 连接 HOJ 的 MySQL 数据库

### 环境变量

| 变量名 | 说明 | 必填 |
|--------|------|------|
| `SERVER_PORT` | 服务端口 | 否（默认 8080） |
| `DATABASE_HOST` | 数据库地址 | 是 |
| `DATABASE_USER` | 数据库用户名 | 是 |
| `DATABASE_PASSWORD` | 数据库密码 | 是 |
| `HOJ_API_BASE_URL` | HOJ 后端地址 | 是 |
| `JWT_SECRET` | JWT 密钥 | 是（需与 HOJ 一致） |
