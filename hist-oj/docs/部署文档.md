# Hist-OJ 部署文档

## 文件说明

| 文件                  | 说明                        |
|---------------------|---------------------------|
| Dockerfile          | Docker 镜像构建，端口 8080，含健康检查 |
| docker-compose.yml  | 容器编排，需填写占位符               |
| configs/config.yaml | 配置文件模板                    |
| Makefile            | 常用命令封装                    |
| migrations/init.sql | 数据库初始化脚本                  |
| README.md           | 部署说明                      |

## 需要填写的占位符

在 `docker-compose.yml` 文件中，需要填写以下占位符：

- `<---HOJ数据库地址，如果同一docker网络填容器名，否则填IP--->` - HOJ 数据库地址
- `<---数据库用户名--->` - 数据库用户名
- `<---数据库密码--->` - 数据库密码
- `<---HOJ后端地址，如 http://hoj-backend:6688--->` - HOJ 后端 API 地址
- `<---与HOJ一致的JWT密钥--->` - JWT 密钥（必须与 HOJ 的 `jwt-token-secret` 一致）
- `<---HOJ的docker网络名--->` - HOJ 的 Docker 网络名称（如果使用 Docker 部署）

## 部署步骤

### 1. 初始化数据库

在 HOJ 数据库中执行初始化脚本：

```bash
mysql -h <数据库地址> -u <用户名> -p hoj < migrations/init.sql
```

**说明：**
- `-h` 指定数据库地址（IP 或主机名）
- `-u` 指定数据库用户名
- `-p` 会提示输入密码
- `hoj` 是数据库名称
- `migrations/init.sql` 是初始化脚本路径

脚本会创建以下表：
- `rating_history` - Rating 历史记录表
- `contest_rating_status` - 比赛 Rating 状态表
- 在 `user_record` 表中新增 `hist_rating` 字段

### 2. 填写 docker-compose.yml 中的占位符

编辑 `docker-compose.yml` 文件，将所有占位符替换为实际值：

```yaml
environment:
  # 数据库配置
  - DATABASE_HOST=<HOJ数据库地址>
  - DATABASE_USER=<数据库用户名>
  - DATABASE_PASSWORD=<数据库密码>
  
  # HOJ 后端 API 地址
  - HOJ_API_BASE_URL=<HOJ后端地址>
  
  # JWT 配置（必须与 HOJ 一致）
  - JWT_SECRET=<JWT密钥>

networks:
  - <HOJ的docker网络名>
```

**注意事项：**
- 如果 hist-oj 与 HOJ 在同一 Docker 网络中，数据库地址填写容器名（如 `hoj-mysql`）
- 如果不在同一网络，填写数据库的 IP 地址
- JWT 密钥必须与 HOJ 后端配置的 `jwt-token-secret` 完全一致
- 如果 HOJ 使用 Docker 部署，需要加入同一网络以便服务间通信

### 3. 一键部署

执行部署命令：

```bash
make deploy
```

**说明：** 该命令会执行以下操作：
- `docker-build` - 构建 Docker 镜像
- `docker-run` - 启动容器（`docker-compose up -d`）

### 4. 验证部署

检查服务是否正常运行：

```bash
curl http://localhost:8080/health
```

如果返回正常响应，说明服务已成功启动。

## 配置说明

### 环境变量

| 变量名 | 说明 | 默认值 | 必填 |
|--------|------|--------|------|
| `SERVER_PORT` | 服务端口 | 8080 | 否 |
| `DATABASE_HOST` | 数据库地址 | - | 是 |
| `DATABASE_PORT` | 数据库端口 | 3306 | 否 |
| `DATABASE_USER` | 数据库用户名 | - | 是 |
| `DATABASE_PASSWORD` | 数据库密码 | - | 是 |
| `DATABASE_DBNAME` | 数据库名称 | hoj | 否 |
| `HOJ_API_BASE_URL` | HOJ 后端 API 地址 | - | 是 |
| `JWT_SECRET` | JWT 密钥 | - | 是 |
| `RATING_INITIAL_RATING` | 初始 Rating | 1500 | 否 |
| `RATING_K_FACTOR` | K 值 | 32 | 否 |
| `RATING_CHECK_INTERVAL` | 检查间隔（分钟） | 5 | 否 |

### 健康检查

Dockerfile 中配置了健康检查，每 30 秒检查一次：

```dockerfile
HEALTHCHECK --interval=30s --timeout=3s --start-period=5s --retries=3 \
    CMD wget --no-verbose --tries=1 --spider http://localhost:8080/health || exit 1
```

## 故障排查

### 查看日志

```bash
make docker-logs
```

或查看最近 100 行日志：

```bash
docker-compose logs --tail=100 -f
```

### 检查容器状态

```bash
make status
```

或：

```bash
docker-compose ps
```

### 常见问题

1. **无法连接数据库**
   - 检查数据库地址、用户名、密码是否正确
   - 确认数据库是否允许远程连接
   - 如果在 Docker 网络中，确认网络配置正确

2. **无法连接 HOJ 后端**
   - 检查 `HOJ_API_BASE_URL` 是否正确
   - 确认网络连通性
   - 如果在 Docker 网络中，确认已加入同一网络

3. **JWT 验证失败**
   - 确认 `JWT_SECRET` 与 HOJ 后端的 `jwt-token-secret` 完全一致
   - 检查是否有空格或特殊字符

4. **健康检查失败**
   - 检查服务是否正常启动
   - 查看容器日志排查错误
