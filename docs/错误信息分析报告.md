# 判题错误信息分析报告

## 一、当前实现分析

### 1. 本地样例测试（已实现✅）

**数据流程**：
```
代码提交 → HOJ API (/judge) → go-judge沙盒执行
    ↓
返回 TestJudgeRes:
{
  "status": 3,           // -2=CE, -1=WA, 0=AC, 1=TLE, 2=MLE, 3=RE
  "output": "50\n",
  "stderr": "Division by zero",  ← 错误信息
  "expectedOutput": "30"
}
```

**返回的错误信息**：
- ✅ **包含**: stderr 原始输出
- ❌ **不包含**: 源代码行号
- ❌ **不包含**: 函数调用栈

**示例**：
```cpp
// 代码
int main() {
    cout << "50" << endl;
    int x = 1 / 0;  // 第3行
}
```

**返回**：
```json
{
  "stderr": "Floating point exception"
}
```

**无法得到**：
```
Division by zero (main.cpp:3)
```

### 2. 远程判题（已扩展✅）

**数据流程**：
```
代码提交 → BingoJ API → HOJ后端 → go-judge沙盒
    ↓
返回 JudgeResult:
{
  "submitId": 12345,
  "status": 3,
  "time": 10,
  "memory": 1024,
  "errorMessage": "Runtime Error",  ← 状态描述
  "score": 0
}
```

**当前问题**：
- ❌ JudgeResult 的 `errorMessage` 只包含状态描述
- ❌ **不包含** stderr 详细错误信息
- ❌ **不包含** 行号或堆栈信息

---

## 二、为什么无法获取行号信息？

### 技术限制

#### 1. **Stderr 本身的限制**
```bash
# 程序运行时的 stderr 输出
$ ./test
Floating point exception  ← 只有错误类型
Segmentation fault        ← 只有错误类型
```

**不会自动包含**：
- 源代码文件名
- 错误发生的行号
- 函数调用栈

#### 2. **编译优化的影响**
```bash
# 默认编译（带优化）
g++ code.cpp -o test
# 崩溃时只显示：
Segmentation fault

# 调试编译（无优化，带符号）
g++ -g code.cpp -o test
# 崩溃时显示：
Segmentation fault (core dumped)
# 但仍然没有行号
```

#### 3. **沙盒安全限制**
- go-judge 为了安全，限制了许多功能
- 不允许访问源代码文件
- 不能使用 addr2line 等工具
- 不能生成 core dump 文件

---

## 三、获取行号的可能方案

### 方案1：编译时添加调试符号（推荐⭐）

**实现方式**：
```bash
# 修改编译命令
g++ -g -O0 -fno-omit-frame-pointer code.cpp -o test
```

**使用工具解析**：
```bash
# 运行程序
./test
# 崩溃后生成 core 文件

# 使用 addr2line 获取行号
addr2line -e test -f core
# 输出:
# /hoj/run/main.cpp:15 (discriminator 2)
```

**在HOJ中的实现**：
```go
// 1. 编译时添加 -g 标志
cmd := exec.Command("g++",
    "-g", "-O0", "-fno-omit-frame-pointer",
    sourceFile, "-o", outputFile)

// 2. 捕获 stderr
stderr, _ := cmd.CombinedOutput()

// 3. 如果崩溃，解析 core dump 或使用 addr2line
if status == 3 { // RE
    if strings.Contains(stderr, "Segmentation") {
        // 使用 addr2line 解析
        lineInfo := runAddr2Line(outputFile, coreFile)
        stderr += fmt.Sprintf("\n    at %s", lineInfo)
    }
}
```

**优点**：
- ✅ 可以定位到具体行号
- ✅ 标准做法，可靠性高

**缺点**：
- ⚠️ 需要修改 HOJ 后端编译逻辑
- ⚠️ 增加编译时间和判题时间
- ⚠️ core dump 文件占用空间

---

### 方案2：使用 Address Sanitizer（ASan）

**实现方式**：
```bash
# 编译时添加 ASan
g++ -fsanitize=address -g code.cpp -o test
```

**运行输出**：
```
==12345==ERROR: AddressSanitizer: heap-use-after-free on address 0x...
    #0 0x555555 in main /hoj/run/main.cpp:15
    #1 0x555555 in __libc_start_main /lib/x86_64-linux-gnu/libc.so.7
```

**优点**：
- ✅ 自动包含行号
- ✅ 能检测内存泄漏、越界等问题
- ✅ Google 开发，稳定性好

**缺点**：
- ⚠️ 需要修改 HOJ 后端
- ⚠️ 程序运行变慢（2-5倍）
- ⚠️ 内存占用增加

---

### 方案3：手动在代码中添加日志（最简单）

**代码示例**：
```cpp
#include <iostream>
using namespace std;

int main() {
    cout << "50" << endl;
    cerr << "[DEBUG] Before division, line 5" << endl;

    int x = 1 / 0;  // 可能出错

    cerr << "[DEBUG] After division" << endl;
    cout << x << endl;
}
```

**返回的 stderr**：
```
[DEBUG] Before division, line 5
Floating point exception
```

**优点**：
- ✅ 无需修改后端
- ✅ 立即可用
- ✅ 可以精确定位

**缺点**：
- ❌ 需要手动修改代码
- ❌ 不能用于已经提交的代码

---

### 方案4：编译错误已经包含行号

**编译错误示例**：
```cpp
int main() {
    int x = 1 / 0;  // 错误：除零，在编译时会被警告
}
```

**编译器输出**（已经包含行号）：
```
main.cpp: In function 'int main()':
main.cpp:3:12: warning: division by zero [-Wdiv-by-zero]
     int x = 1 / 0;
            ~~^~~^
```

**HOJ 已经实现了CE的详细信息显示**：
```json
{
  "status": -2,  // CE
  "errorMessage": "main.cpp:3:12: error: expected ';' before 'x' token"
}
```

**结论**：
- ✅ **编译错误（CE）已经包含行号**
- ✅ **运行时错误（RE）不包含行号**

## 四、实际测试结果

### 测试代码1：段错误
```cpp
#include <iostream>
using namespace std;

int main() {
    int* p = nullptr;
    *p = 5;  // 第6行：段错误
    cout << *p << endl;
    return 0;
}
```

**当前返回**：
```json
{
  "stderr": "Segmentation fault"
}
```

**期望返回**（使用方案1）：
```
Segmentation fault
    at main.cpp:6
```

---

### 测试代码2：数组越界
```cpp
#include <iostream>
using namespace std;

int main() {
    int arr[5];
    cout << arr[100] << endl;  // 第6行：越界访问
    return 0;
}
```

**当前返回**：
```json
{
  "stderr": ""  // 空的！
}
```

**实际输出**：
```
（无输出，直接崩溃）
```

**说明**：某些类型的错误（如数组越界）可能不会产生 stderr 输出

---

### 测试代码3：断言失败
```cpp
#include <cassert>
#include <iostream>

int main() {
    int x = 5;
    assert(x == 10);  // 第6行：断言失败
    cout << x << endl;
    return 0;
}
```

**当前返回**：
```json
{
  "stderr": "test: main.cpp:6: int main(): Assertion `x == 10' failed."
}
```

**惊喜**：✅ **assert 已经包含行号信息！**

## 五、总结与建议

### 当前情况
| 错误类型 | 能否获取原因 | 能否获取行号 | 说明 |
|---------|------------|------------|------|
| CE (编译错误) | ✅ 是 | ✅ 是 | 编译器自动提供 |
| RE - assert | ✅ 是 | ✅ 是 | assert 包含行号 |
| RE - 段错误 | ✅ 部分 | ❌ 否 | 只有错误类型 |
| RE - 越界 | ⚠️ 可能 | ❌ 否 | 可能无输出 |
| RE - 除零 | ✅ 是 | ❌ 否 | 有错误类型 |

### 建议方案

#### 短期（立即可用）
1. ✅ **已实现**：显示 stderr 错误信息
2. ✅ **提示用户**：鼓励使用 assert 定位错误
3. ✅ **文档说明**：告知用户如何获取详细错误信息

#### 长期（需要修改HOJ后端）
1. **方案1**：编译时添加 `-g` 符号，使用 addr2line
2. **方案2**：使用 Address Sanitizer (-fsanitize=address)
3. **优先级**：方案2 > 方案1（ASan更准确，更容易实现）

## 六、用户指南

### 如何获取更详细的错误信息？

#### 方法1：使用 Assert（推荐）
```cpp
#include <cassert>
#include <iostream>
using namespace std;

int main() {
    int a, b;
    cin >> a >> b;

    assert(b != 0 && "Divisor cannot be zero!");  // 添加断言
    cout << a / b << endl;

    return 0;
}
```

**错误输出**：
```
test: main.cpp:10: int main(): Assertion `b != 0 && "Divisor cannot be zero!"' failed.
```

#### 方法2：手动添加调试日志
```cpp
int main() {
    int* p = nullptr;
    cerr << "[DEBUG] Before dereference, line 6" << endl;
    *p = 5;
    return 0;
}
```

#### 方法3：使用调试工具
```bash
# 本地编译时添加调试符号
g++ -g -O0 code.cpp -o test

# 运行并生成 core dump
ulimit -c unlimited
./test

# 分析 core dump
gdb test core
(gdb) bt  # 查看调用栈
(gdb) frame 0  # 查看当前帧
```

## 七、结论

**当前实现**：
- ✅ 可以显示 stderr 错误信息
- ❌ 无法自动定位到源代码行号

**技术原因**：
- Stderr 本身不包含行号信息
- go-judge 沙盒限制了调试功能
- 编译优化去除了符号信息

**解决方向**：
1. 短期：鼓励使用 assert 或手动日志
2. 长期：修改 HOJ 后端编译选项（-g 或 -fsanitize）
