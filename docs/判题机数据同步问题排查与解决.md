# 判题机数据同步问题排查与解决

## 问题描述

### 时间
2025-01-24

### 现象
重新部署项目后，重启判题机，但评测一直报 **System Error**，数据没有同步到判题机。

### 环境
- **主服务器**：43.143.133.62（运行 HOJ 后端服务）
- **判题机1**：120.53.239.108
- **判题机2**：82.156.29.203
- **判题机工作目录**：`/workspace/hoj-deploy/distributed/judgeserver`
- **SSH 密码**：`n208966737.`（判题机 ubuntu 用户）、`n208966737`（主服务器 root 用户）

## 解决方案

### 重启 rsync master 容器

根据 [HOJ 官方文档](https://docs.hdoi.cn/monomer/rsync/)，采用简单重启方式：

```bash
ssh ubuntu@43.143.133.62 "sudo docker start hoj-rsync-master"
```

**执行结果**：
```
hoj-rsync-master
```

### 验证容器启动状态

```bash
# 检查容器状态
ssh ubuntu@43.143.133.62 "sudo docker ps | grep hoj-rsync-master"

# 检查端口监听
ssh ubuntu@43.143.133.62 "sudo ss -tlnp | grep 873"

# 查看 rsync 进程
ssh ubuntu@43.143.133.62 "sudo docker exec hoj-rsync-master ps aux | grep rsync"
```

## 总结

### 问题根因

主服务器的 `hoj-rsync-master` 容器异常停止，导致判题机无法同步评测数据，进而导致所有提交的代码都报 System Error。

### 解决方案

重启 `hoj-rsync-master` 容器即可恢复服务。

### 经验教训

1. **监控重要性**：应设置容器监控，及时发现容器停止
2. **日志检查**：判题机的 rsync 日志是排查问题的关键
3. **网络诊断**：使用 `nc` 或 `telnet` 测试端口连通性
4. **数据验证**：同步后要验证数据完整性

### 后续优化建议

1. **设置监控告警**：当容器停止时发送告警通知
2. **定期备份**：定期备份评测数据，防止数据丢失
3. **健康检查**：配置 Docker 健康检查，自动重启异常容器
4. **日志轮转**：配置 rsync 日志轮转，避免日志文件过大
